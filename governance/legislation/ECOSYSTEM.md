# InterDeadIT ecosystem engineering legislation

Revision: `1.0.0`. Status: `operative`. Authority: Founding Profile P05/P10.

## ECO-001 — Source and configuration
Runtime links use declared configuration. The studio domain is `zhovten.games`; site, API and prototype defaults are recorded in the ecosystem registry. Preserved historical fixtures and externally pinned sources keep their original bytes. Domain changes update consumers, canonical URLs, OAuth redirects and host settings together.

## ECO-002 — Explicit dependency boundaries
InterDeadCore supplies web packages; InterDead owns the portable C++ Session; SPIDER supplies method and reviewed literary examples. A dependency is declared by contract and pin. The seven-repository navigation is a catalogue, not an import graph.

## ECO-003 — Verification
`node tools/warden.mjs` is the complete repository verification entry. Existing unit, integration, native, overlay and methodology drivers remain its adapters. Failure or absence of a mandatory driver is a failed delivery. Reports identify scope and source. A generated local report cannot certify a deployed site or unobserved physical hardware.

## ECO-004 — Compatible style and artifacts
Follow P16's selected language, filenames, formatting and local overrides. Preserve data and external source provenance. Build outputs, vendored third-party code, session recordings and historical fixtures have explicit derivative/external scope. New generated dependencies stay outside source commits. New regression coverage exercises a changed invariant through the production boundary.

## ECO-005 — Publication and access
Secrets are configured at the consuming host with minimal scope. Public documentation carries no private source, save data or credential value. Cloudflare, Discord and itch configuration is applied in the declared order. This patch authorizes local engineering adoption; external deployment is performed by the owner through the supplied runbook.
